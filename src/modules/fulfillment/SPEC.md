# Portal fulfillment rules — v11

Admin/owner configure one revisioned policy: delivery/pickup enabled flags, bilingual pickup address, pickup minimum, ISO closed weekdays, explicit closed dates, named bilingual delivery zones with disjoint active six-digit Romanian postal-code lists, per-zone fee/minimum (integer bani), and weekly time slots with mode, weekday set, start/end and order capacity. Adjacent slots are allowed; overlapping active slots of the same mode are not. Each request reserves one slot place, independently of item/portion limits. Requests and confirmed orders reserve places; rejection/cancellation releases them. Pending requests do not automatically expire.

Missing policy closes NEW portal ordering. No invented production zones, fees, address or schedule is seeded. Existing orders remain usable, historical pickup/delivery data and prices are immutable. This does not change prior orders or daily-menu configuration. Both the daily menu and the fulfillment policy must allow the date; explicit closure overrides an otherwise open menu. Every portal request must choose an available mode and compatible slot. Delivery requires a matching exact declared postal code and nonempty saved address. Postal code is customer-declared; the staff review must verify it agrees with the delivery address. No geocoding or distance calculation. Pickup does not require a private delivery address. UTC deadlines and future local slots use Europe/Bucharest; nonexistent/ambiguous DST slots are unavailable.

The customer sees item subtotal, shipping fee and grand total before submit; snapshots include chosen interval, zone labels, minimum, fee and pickup address. Quote fingerprint includes policy revision. Submit rechecks policy revision inside the transaction, then a database trigger enforces slot availability/capacity. Changing capacity below already-booked future counts is forbidden transactionally; slot identity (mode/weekdays/start/end) can be edited while no order references the slot; once any order references it, the identity is fixed for that ID, including after deletion/recreation. The settings API returns the booked slot IDs so the UI locks only those fields; the save transaction re-checks that no order references an edited slot (v18). Old slots may be disabled/removed without cancelling bookings. Retrying the same submission does not reserve another place. Staff reviews/accepts the saved quote without recalculating prices from new policy.

Pickup orders stay out of courier assignment/manifests. Ready confirmed pickups go directly pending→delivered when handed over; no transit/failure/courier path. Paid state remains independent. Shared state guards, revision checks and audit apply. Internal manual and recurring orders currently remain explicit staff exceptions: no automatic zone fees or slot reservations unless a slot is present; dated dish-capacity limits still apply. The settings UI labels these rules as portal rules. Global kitchen capacity, route planning, courier mobile login and fiscal receipts are separate modules.

All changes require same-origin authenticated JSON. Admin/owner write settings; dispatcher may inspect them; other roles cannot access internal settings. Public API returns only customer-safe policy/availability, no customer/order identities. Non-sales projections strip fee, postcode and private fulfillment snapshot. Audit records and order/line creation are atomic. Policy state/transition rules do not alter existing order snapshots.

Acceptance: unsupported postcode, insufficient food subtotal, closed day, disabled mode, stale policy quote and full slot reject requests. Two concurrent requests for the last slot yield one order. Cancellation restores the place. Fee edits leave existing totals unchanged. Pickup can be handed over only after ready and never assigned a courier. HU/RO settings and portal, reload, daily menu regression and role boundaries are verified.

## Rendelésszám-korlát megszűnt — v50
A heti idősávoknál a „rendelések száma / nap” (`capacity`) mező és minden hozzá tartozó ellenőrzés megszűnt: nincs se minimális, se maximális rendelésszám idősávonként. Kikerült a szerkesztőből, a portál nem mutat „szabad helyet”, a rendeléskor nincs darabszám-ellenőrzés, a mentéskori ellenőrzés sem fut, és a `order_fulfillment_capacity` adatbázis-trigger is törlődött (`0023_drop_slot_capacity_trigger`). A régi mentett szabályokban szereplő `capacity` értéket a rendszer figyelmen kívül hagyja, és a következő mentéskor elhagyja. A minimális rendelési összeg (átvétel, zónák) változatlanul beállítható.

## Települések irányítószám helyett, idősávok nélkül — v58
Ez a szakasz felülírja a fenti irányítószámos és idősávos szabályokat.
- **Körzet = település.** Egy körzet: azonosító, név magyarul és románul, szállítási díj, minimum ételérték, engedélyezve. Irányítószám nincs; a vásárló a portálon a település nevére kattint, a kérés a körzet azonosítóját (`zoneId`) viszi. Két aktív körzetnek nem lehet ugyanaz a (magyar) neve (`FULFILLMENT_ZONE_OVERLAP`). Legfeljebb 30 körzet.
- **Díj később is beállítható.** Most minden körzet díja 0 (ingyenes kiszállítás); a díj és a minimum körzetenként átírható, és a rendelésbe pillanatképként kerül.
- **Nincsenek heti idősávok.** A vásárló vagy „Minél előbb”-et választ (`time` üres), vagy kívánt időpontot ad meg (óó:pp), ami mai, még el nem múlt időpont kell legyen (Europe/Bucharest), különben `FULFILLMENT_SLOT` / `PORTAL_SLOT`. „Minél előbb” esetén a rendelés `time` mezője a beküldés ideje, így a konyha a beérkezés sorrendjében látja.
- **Pillanatkép:** `{mode, zoneId, asap, start (kívánt időpont vagy üres), end: '', zoneHu, zoneRo, addressHu, addressRo, minimum, fee}`; `slotId`, `weekdays`, `postalCode` üres. Az `orders.fulfillment_slot_id` NULL, a `fulfillment_postal_code` üres. A régi rendelések idősávos pillanatképe változatlan, és „11:00–12:00” alakban jelenik meg.
- **Régi mentett szabály:** betöltéskor a `slots` és a körzetek `postcodes` mezője kimarad, a következő mentés már nélkülük írja. Migráció nem kell (a szabály JSON-ban van).
- Változatlan: mód engedélyezése, átvételi cím és minimum, heti zárvatartás és zárt napok, szerveroldali díj- és minimumszámítás, változatlan ár a beküldésig (`quote`).
